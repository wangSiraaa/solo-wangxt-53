# 公益仓库离线扫码装箱与交接清单系统

一台**离线电脑**连续扫描捐赠物资：边评估成色边装箱、生成交接清单。
纯前端 **Svelte 4 + TypeScript + Vite**，扫码用 **ZXing（@zxing/browser）**，
数据全部在本机 **IndexedDB**，**无后台、无网络请求**。

## 启动（离线方式）

```bash
npm install          # 首次（联网机器上执行，或把整个工程目录拷过去）
npm run dev          # 开发：http://127.0.0.1:5173
# 或
npm run build        # 产物在 dist/，可用任何静态服务器/文件方式打开
npm run preview
npm test             # 30 个测试（vitest + fake-indexeddb）
npm run check        # svelte-check 类型检查
```

> 摄像头要求 https 或 localhost；用 `127.0.0.1` 访问即可。无摄像头/无权限时
> 系统自动降级到键盘（扫码枪等价于键盘回车）和文件导入，业务不中断。

## 数据模型与规则一览

- **身份模型（多工程合并的关键）**：每件物品的稳定身份是 `itemId = 来源工程ID#创建操作uid`，
  条码只是**可人工改写的属性**（RELABEL，旧码进 aliases）。每条操作都带
  `(projectId, uid, seq)`：uid 全局去重、seq 是该工程内因果顺序，
  `at` 只是该电脑本机时钟，**合并判定不使用 at**。
- **Item（物品）**：itemId 为稳定主键。重复扫描只定位原物品并累加 `scanCount`，
  日志记 `RESCAN`，**绝不产生第二份库存**。
- **Box（箱）/Organization（机构）**：全局引用 `projectId#localId`，各工程箱互不串号。
- 装箱必须同时通过：**机构品类、机构成色、箱品类、箱成色、高价值复核结论**五类检查，
  任一不过逐条列出原因（`src/lib/rules.ts: validatePack`）。
- 高价值物品须先复核（可多次追加，以最后一条结论为准）。
- 交接 = 逐件勾检 + 每件仍适配，全部满足才锁定。锁定后清单只读，
  错误只能走**退回（RETURN）**，交接与退回记录都保留。
- 操作日志（`logs`）**只追加**：撤销 = 追加 `REVERT` 补偿记录，不删历史行；
  扫码之后若已追加复核，撤销被直接阻止，**复核记录不会被误删**。
- **移箱**在单个 IndexedDB 事务内同时改物品、来源箱（清勾检）、目标箱、日志，
  目标箱校验失败整笔回滚（`src/lib/actions.ts: moveItem`）。

## 两个离线仓库的工程合并（「工程合并」页）

`src/lib/merge.ts` 是纯函数合并引擎，`src/lib/merge-actions.ts` 负责预览/裁决/提交。

- **可预览、不写库**：载入对方工程快照后先列出新增操作数、跳过数、全部冲突，可反复预览。
- **稳定操作编号去重**：操作按 `projectId#uid` 去重。完全相同的操作只导入一次；
  **重新导入同一包**，新增为 0、全部计入“跳过”，已处理冲突不再出现（裁决按证据指纹签名校验）。
- **同一条码被两边独立创建**：列为 `ITEM_COLLISION` 待裁决，**绝不自动加总库存**。
  人工二选一：① 同一实物 → loser 身份并入 winner（库存仍为 1，两份记录都留痕）；
  ② 不同实物 → 给其中一件改派新条码（不新增、不合并）。
- **已交接事实不被旧成色覆盖**：HANDOVER 带交接时刻证据快照；单一现存交接时，
  另一工程的较旧 GRADE/位置只生成 `BLOCKED_STALE_GRADE` 信息项，不覆盖事实。
- **同一实物被记录交给两个机构** `DUAL_HANDOVER`：**冻结后续一切转移**，
  两份交接证据（机构、接收人、成色、条码、时间；即使其中一次后来已退回，
  证据标记 `active=false` 仍保留）并列展示，由人工核实选定去向。
- **其他冲突**：`DAMAGE`（两边成色不一致）、`LOCATION`（去向不一致）均需人工裁决；
  `ALIAS_COLLISION`（当前码撞上对方曾用码）为信息项。
- **可暂停**：先提交部分裁决，未决物品保持冻结/待裁决；之后随时再导入同一包继续，
  已处理操作和已处理冲突都不会重复。
- **时钟无关 & 顺序无关**：规范状态由「各工程按自身 seq 独立折叠后再比对」产生，
  排序键仅 `(projectId, seq, uid)`；先导入哪个工程、两机时钟差多少，结果一致
  （测试 `顺序无关（含裁决与交接证据）`）。

合并台账（已导入操作、裁决）随工程快照导出，所以“同一包不再重复处理”在换机后依然成立。

## 三个预置案例（首次打开自动载入演示数据）

演示数据可在「清单/工程导出」页随时 **重置为演示数据**。

### 案例 1：摄像头不可用
1. 打开「扫码队列」，勾选 **「模拟摄像头不可用（离线演练）」**，点「启动摄像头扫码」；
   也可不勾选直接在没有摄像头的机器上点启动。
2. 出现黄色降级横幅，说明结构化原因（无设备/权限拒绝/非安全上下文），
   **键盘录入框自动可用**：输入条码回车即入队。
3. 「文件导入」页可继续批量导入，队列/装箱/交接/导出全部不受影响。
   规则覆盖见 `src/test/scanner.test.ts`（NO_MEDIA_API / PERMISSION_DENIED / NO_DEVICE）。

### 案例 2：重复扫描定位原物品
1. 队列页键盘输入 `6901001` 回车 —— 该码是箱 A-01 内已复核的儿童羽绒服。
2. 提示「重复条码…已定位原物品，已在【箱 box-a01】内，未新增库存」；
   连扫 N 次，库里始终只有 1 件，`scanCount` 增加，日志多一条 `RESCAN`。
3. 「文件导入」载入 `sample-import.csv`：其中 `6901001` 与库内重复，
   结果区把它归入“重复（未入库）”。

### 案例 3：一箱混入不适配物品
1. 切到「箱内明细/交接」选 **A-01**（爱华福利院：仅衣物、成色 ≤1）。
2. 队列中的 **毛绒玩具（污渍）6901003**：品类 toy、成色 3。预检列直接标红：
   “该箱仅收纳限定品类…”“成色 3级 超出箱上限 1级”“超出机构上限”，装入按钮禁用。
3. 即使物品已在箱内，交接区也**逐件列出**每件状态：未勾检 / 不适配，
   必须每件勾检且 0 阻断项，「整箱交接并锁定」才可点 —— 不是仅靠一个禁用按钮。
4. 箱 C-03 是**已交接锁定**样例：不能再编辑；点「交接有误·退回处理」，
   填原因后解锁修正，HANDOVER/RETURN 两行日志都保留。

### 撤销连续扫码（不毁复核）
- 队列物品行有「撤销扫码」：仍在队列、其后无复核记录才允许；
- 对已复核的高价值物品（先在队列页给它加复核再试）会被阻止并提示原因；
- 已装箱物品须先取出。撤销后物品消失，但 SCAN 原行保留、新增 REVERT 行。

## 导出物（全部离线生成）

- **待交接清单 HTML** 与 **已交接清单 HTML**：两类文件分开，已交接文件带
  「🔒 已交接 · 锁定」标识与接收人（含曾用码、稳定身份、冻结提示）；可直接浏览器打印签字。
- **单箱清单**：箱详情页「导出本箱清单」。
- **工程快照 JSON**（`charity-warehouse/v2`）：含工程元信息（projectId）、合并台账、
  机构、物品、箱、全部操作日志（稳定 uid+seq、交接证据），可在另一台离线电脑
  「恢复工程快照」重新打开，或在「工程合并」页作为对方工程包导入。
- 导出页提供 **一键并入 P2 演示工程** 与 **下载 P2 快照**；命令行可跑
  `npm run demo:merge`（合并验收）与 `npm run demo`（单机流程）。

```
scripts/                e2e-demo.ts（单机）、merge-demo.ts（合并验收）
```
